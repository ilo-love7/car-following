# 数据来源与数据字典

## 一、数据来源

本项目的数据策略是「**自包含合成基准（默认）+ 真实数据适配器（可选）**」，以保证仓库**零外部依赖即可复现**，同时保留接入真实公开数据集的能力。

### 1.1 合成基准（默认，仓库自带）

由 `carfollowing.datasets.synthetic` 生成，物理含义如下：

* **前车**：给定一条"真实感"速度剖面 `realistic_speed_profile(t)`，由
  慢速漂移 + 正弦交通波 + 若干高斯形制动事件叠加而成（长度 300 s、`dt=0.1 s` 量级）；
* **后随车**：以**异构 IDM** 驾驶员跟驰前车，参数（`v0, T, s0, a, b`）从总体先验范围内抽样，
  可选叠加测量噪声（默认无）；
* 输出接口：`PlatoonData.pair(i)` → `(leader_trace, t, gap, speed)`，与真实数据抽取结果**接口一致**，便于互换。

固定随机种子即可完全复现。这是 case 1–7 以及 case 8 夹具的默认数据来源。

### 1.2 NGSIM（可选，真实数据）

* **名称**：Next Generation Simulation (NGSIM) Vehicle Trajectories
* **发布方**：美国联邦公路局 FHWA
* **获取**：data.gov 收录条目 "Next Generation Simulation (NGSIM) Vehicle Trajectories"
  典型路段：US-101、I-80、Lankershim Boulevard、Peachtree Street
* **格式**：纯文本（制表符/逗号分隔），10 Hz，美国惯用单位（位置 ft、速度 ft/s、全局时间 ms）
* **用法**：将文本文件放入 `data/ngsim/`，`scripts/case8_ngsim.py` 会自动使用；否则脚本使用合成夹具验证链路。
* **说明**：真实数据体积较大且受下载/许可约束，**未随仓库分发**。

### 1.3 highD（备选，仅说明）

* **名称**：highD Dataset（Krajewski et al., 2018）
* **获取**：https://levelxdata.com/highd-dataset/（约 16.5 小时、11 万车辆、45,000 公里）
* **与 NGSIM 差异**：无人机俯拍、坐标以 m 计、无需单位换算；接入时只需把 `load_ngsim` 的列名/单位映射换掉。
  当前仓库未实现 highD 适配器，但列映射为纯配置，可按需扩展。

## 二、数据字典

### 2.1 合成基准 `PlatoonData`

| 字段 | 类型 | 单位 | 含义 |
|---|---|---|---|
| `t` | `np.ndarray (n,)` | s | 时间戳 |
| `trajectories[i]["x"]` | `np.ndarray (n,)` | m | 第 i 车位置（i=0 为前车） |
| `trajectories[i]["v"]` | `np.ndarray (n,)` | m/s | 第 i 车速度 |
| `trajectories[i]["s"]` | `np.ndarray (n,)` | m | 第 i 车到前车的净距（i=0 无） |
| `params[i]` | `dict` | — | 第 i 后随车的 IDM 真值参数（用于 case4 校验） |
| `n_vehicles` | `int` | — | 车辆总数（含前车） |

### 2.2 NGSIM 原始列（`load_ngsim` 读入）

| 原始列 | 单位 | 内部字段 | 换算 |
|---|---|---|---|
| `Vehicle_ID` | — | `vid` | — |
| `Frame_ID` | — | `frame` | — |
| `Global_Time` | ms | `t` | `(time − t_min)/1000` → s |
| `Local_X` | ft | `x` | `× 0.3048` → m |
| `Local_Y` | ft | `y` | `× 0.3048` → m |
| `v_Vel` | ft/s | `v` | `× 0.3048` → m/s |
| `v_Acc` | ft/s² | `acc` | `× 0.3048` → m/s² |
| `Lane_ID` | — | `lane` | — |
| `Preceding` | — | `prec` | 前车 ID（0 表示无） |
| `Following` | — | `foll` | 后车 ID（0 表示无） |

### 2.3 跟驰事件 `FollowingEvent`（`extract_following_events`）

抽取规则：同一 (follow, leader) 组合**连续跟随 ≥ 20 s**，间隙落在 `[2, 80] m`，速度 ≥ 2 m/s。

| 字段 | 单位 | 含义 |
|---|---|---|
| `follower_id`, `leader_id` | — | 车 ID |
| `t` | s | 事件时间轴 |
| `gap` | m | 净距 `= x_lead − x_foll − ℓ` |
| `v` | m/s | 跟驰车速度 |
| `v_lead` | m/s | 前车速度 |
| `x_lead` | m | 前车位置 |
| `leader_trace()` | — | 返回 `LeaderTrace`，供仿真/标定使用 |

## 三、生成与复现

```bash
# 生成全部数据产物（CSV / JSON / NGSIM 夹具）
python scripts/run_all.py

# 数据产物位置
data/
├── summary.json               # 所有案例关键指标汇总
├── metrics_case1..8.json      # 各案例结构化结果
├── case1_fd_*.csv             # 各模型基本图
├── case2_idm_stability_grid.csv
├── case4_model_selection.csv
├── case6_lane_changes.csv
├── case7_styles.csv / consumption_curve.csv
├── case8_event0.csv
└── ngsim_fixture.txt          # 合成 NGSIM 格式夹具（case8）
```

所有随机过程使用固定种子（见各 `case*.py`），结果确定、可逐位复现。
